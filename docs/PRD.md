# PRD — XRL DEMONSTRATION 门户首页

## 产品目标

- 为 `demo.xrl.im` 提供一个**本身就是作品**的门户首页：访客第一眼即建立强烈的品牌与审美印象，而非看到一个平庸的模板落地页。
- 用一个统一的视觉母题——「规则集合体的简谐运动」（内部设计 DNA，页面不外露）——把四个创意子项目收拢在同一世界观下，对外只呈现 XRL 自己的品牌与作品。
- 把可维护性内建进产品：文案、配色、动画速度都能一处修改、全站同步，让门户能随创意演进长期迭代而不腐化。

## 用户与使用场景

- **目标用户**：
  - 访客 / 观众：被分享链接吸引而来的技术或设计爱好者，来体验视觉作品、了解项目集群。
  - 项目所有者（制作人）：需要频繁微调文案、配色、动画节奏，并把子项目逐个接入门户。
- **典型场景**：
  1. 访客打开 `demo.xrl.im`，看到开机引导转场 → 晶格行波浮现 → 浏览底部四个作品 → 点击某个项目新开标签页进入子站。
  2. 主人想换一句标语 / 加一个项目 / 调慢动画 → 只改一个令牌文件即可，无需理解 3D 或组件细节。
  3. 主人在移动端 / 桌面端分别访问，布局自适应，核心视觉始终成立。

## 核心问题

- 如何让一个纯前端页面既有**艺术表达力**（3D 光影、动效、平面设计的完成度），又有**工程可维护性**（不散落成难以修改的硬编码）？
- 如何让视觉「对味」于既定的美学参照（莱茵生命），而不是泛泛的「科技感」？

## 功能及其意义

| 功能 | 解决什么 | 为什么需要 |
|------|----------|------------|
| 简谐晶格场（3D 主体） | 把「规则集合体的简谐运动」可视化 | 这是整个门户的核心母题与视觉锚点，承载品牌辨识 |
| 反应核心 | 给空间一个构图焦点 | 避免晶格海缺乏视觉重心；呼应「科研装置」意象 |
| 鹰角式 HUD（顶栏/遥测/导航/角标） | 提供信息层与仪器感 | 让 3D 场景读起来像「精密仪器取景框」，而非单纯壁纸 |
| 简谐示波器 | 在平面层复现 3D 的物理法则 | 让 HUD 与 3D 语义咬合，强化「同一套法则」的统一感 |
| 开机引导转场 | 把「加载」变成有剧本的入场 | 掩盖首帧等待、建立仪式感，是鹰角美学的标志性动效 |
| 故障标题（偶发 glitch） | 注入「洁净表象下的失序」 | 呼应莱茵生命的叙事内核，让画面不死板 |
| 项目导航 | 承载四个子项目入口 | 门户的本职——点击新开标签页跳转到同域名下的独立子站 |
| 配色 / 文案 / 动画三令牌 | 一处修改全站同步 | 可维护性的核心，让主人无需碰组件即可调整 |

## 功能之间的关系

- **3D 场景层**是主体与背景；**HUD 层**是其上的信息取景框；二者共享同一套配色（palette）与动画速度（motion），因此在视觉与节奏上是一个整体而非拼贴。
- **示波器**是 3D 简谐法则在 2D 平面的投影，是连接两层的语义纽带。
- **引导转场**先于一切：它决定 HUD 与场景以何种节奏、何种顺序呈现给访客。
- **三令牌系统**横切所有功能：任何视觉 / 文案 / 节奏的调整都经由它们下发到 3D 与 HUD。

## 范围与非目标

- **范围内**：首页的 3D 视觉、HUD 界面、引导转场、响应式适配、配色/文案/动画的可维护性、静态部署。
- **范围外**：
  - 多语言切换（i18n 当前仅用于文案集中管理，不是国际化功能）。
  - 子项目页面本身（门户只提供入口，四个作品的落地页是独立子站，不在本仓库内）。
  - 后端 / 数据 / 用户系统 / 表单交互。
  - SEO 深度优化、埋点分析（原型阶段不涉及）。
